Separacion de responsabilidades

Por que importa y como se aplica en aplicaciones web

Ing. Eduardo Pimienta — Desarrollo Web II

El problema

Cuando todo esta junto en un solo archivo:

  • Encontrar un bug es como buscar una aguja en un pajar
  • Cambiar algo puede romper cosas que no tenian que ver
  • Probar es dificil porque todo depende de todo

SRP — Single Responsibility Principle

Una clase, modulo o funcion debe tener una sola razon para cambiar.

Cada parte del codigo tiene un trabajo y solo un trabajo.

Las tres capas

Presentacion
Logica de negocio
Datos

Cada capa tiene una responsabilidad distinta.

SIN separacion

# TODO EN UN ARCHIVO -asi NO-
@app.get("/courses")
def get_courses():
    db = SessionLocal()
    courses = db.query(Course).all()
    return [{"id": c.id, "name": c.name}
            for c in courses]

CON separacion

Modelo

class Course(Base):
    __tablename__ = "courses"
    id = Column(Integer, primary_key=True)
    name = Column(String)

Servicio

def get_courses(db):
    return db.query(Course).all()

Beneficios

  • Cada archivo tiene UNA responsabilidad
  • Cambiar la BD no afecta los endpoints
  • Cambiar la respuesta no afecta la logica
  • El codigo es mas facil de leer, probar y mantener
